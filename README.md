# ICE Nice

نسخهٔ به‌روزشدهٔ نمونهٔ بازی نقش‌آفرینی ژئوپلیتیکی ICE Nice.

## امکانات این نسخه
- ورود و ثبت‌نام بازیکن و ورود مالک با `ADMIN_USERNAME` و `ADMIN_PASSWORD`
- اعتبار اولیهٔ صفر برای حساب‌های جدید؛ موجودی بازیکنان از پنل مالک قابل تنظیم است
- فهرست ۲۰ ابرقدرت با پرچم، نام کامل فارسی و رتبهٔ قابل تغییر
- مدیریت افزودن/حذف آیتم‌های شاپ و قیمت‌ها از پنل مالک
- روش خرید مستقیم بانکی برای آیتم‌هایی که مالک هنگام افزودن، قیمت تومان تعیین می‌کند؛ خرید اعتباری قبلی بدون تغییر باقی می‌ماند. تحویل پس از تأیید سمت سرور درگاه زرین‌پال انجام می‌شود.
- انتخاب کشور یا سازمان/گروه هنگام ثبت‌نام
- دیپلماسی دوجانبه: انتخاب کشور مقصد، ارسال پیشنهاد سیاسی/تجاری و امکان پذیرش یا رد توسط کشور مقصد
- نقشهٔ تعاملی نشانگرمحور با رنگ و وضعیت قابل تنظیم توسط مالک
- مهاجرت سادهٔ ستون‌های تازه برای پایگاه دادهٔ نسخهٔ قبلی

## استقرار در Render
- Build command: `pip install -r requirements.txt`
- Start command: `gunicorn app:app`
- Environment variables:
  - `SECRET_KEY`: یک مقدار تصادفی و محرمانه
  - `ADMIN_USERNAME`: نام کاربری مالک
  - `ADMIN_PASSWORD`: رمز قوی مالک
  - `DATABASE_URL`: آدرس PostgreSQL پایدار؛ فایل `render.yaml` برای ساخت دیتابیس و اتصال آن تنظیم شده است. اگر سرویس فعلی‌ات از قبل به دیتابیس دیگری وصل است، قبل از استفاده از Blueprint این اتصال را بررسی کن.
  - `ZARINPAL_MERCHANT_ID`: شناسه پذیرندگی واقعی زرین‌پال برای فعال‌سازی پرداخت مستقیم.
  - `ZARINPAL_SANDBOX`: مقدار `1` فقط برای آزمون؛ برای پرداخت زنده مقدار `0` یا متغیر را حذف کن.

در هر شروع برنامه، اگر حساب `ADMIN_USERNAME` از قبل وجود داشته باشد، نقش آن به مالک ارتقا پیدا می‌کند و گذرواژه‌اش با `ADMIN_PASSWORD` همگام می‌شود. این دو متغیر را محرمانه نگه دارید و آن‌ها را در مخزن GitHub قرار ندهید.

## نقشه
نقشهٔ این نسخه از کاشی‌های OpenStreetMap و Leaflet استفاده می‌کند و کشورهای دارای مختصات تعریف‌شده را با نشانگرهای رنگی نمایش می‌دهد. رنگ و وضعیت نشانگرها از پنل مالک تغییر می‌کند. بارگذاری نقشه به اتصال اینترنت مرورگر به سرویس‌های بیرونی وابسته است.

## نکتهٔ مهم دربارهٔ دیتابیس و حساب‌های قبلی
این نسخه از `DATABASE_URL` برای ذخیرهٔ پایدار اطلاعات پشتیبانی می‌کند. اضافه‌کردن دیتابیس PostgreSQL تازه به سرویس موجود به‌خودی‌خود حساب‌های ذخیره‌شده در SQLite قبلی را منتقل نمی‌کند؛ اگر حساب‌های قبلی هنوز در دیتابیس قبلی موجودند، پیش از سوییچ‌کردن اتصال باید از آن‌ها نسخهٔ پشتیبان/مهاجرت تهیه شود. اگر اطلاعات روی دیسک موقت Render قبلاً پاک شده باشند، این کد به‌تنهایی آن حساب‌ها را بازیابی نمی‌کند.

## استقرار امن نسخهٔ جدید
1. از مخزن و دیتابیس فعلی نسخهٔ پشتیبان بگیر.
2. فایل‌ها را در شاخهٔ پروژه جایگزین کن و commit کن.
3. اگر از Render Blueprint برای ساخت PostgreSQL استفاده می‌کنی، ابتدا بررسی کن دیتابیس جدیدی ساخته نشود که ناخواسته جای دیتابیس فعلی را بگیرد.
4. پس از تنظیم `DATABASE_URL` درست، استقرار را انجام بده و ثبت‌نام/ورود و ارسال پیشنهاد دیپلماتیک را آزمایش کن.

## پرداخت مستقیم شاپ
پرداخت مستقیم فقط برای آیتم‌هایی فعال می‌شود که مدیر در پنل مالک هنگام افزودن، فیلد «قیمت خرید مستقیم (تومان)» را پر کند. قیمت اعتبار قبلی و مسیر خرید اعتباری دست‌نخورده باقی می‌مانند. این نسخه اتصال زرین‌پال را پیاده‌سازی می‌کند؛ برای پرداخت واقعی باید شناسه پذیرندگی خودتان را در متغیر محیطی `ZARINPAL_MERCHANT_ID` قرار دهید. ابتدا با `ZARINPAL_SANDBOX=1` آزمایش کنید. تحویل آیتم تنها پس از تأیید پرداخت از سمت سرور انجام می‌شود.


## خبرگزاری: ذخیرهٔ رسانه در PostgreSQL
- عکس‌ها و ویدیوهای آپلودشده در ستون‌های `BYTEA` جدول موجود `news` ذخیره می‌شوند؛ جدول‌ها یا رکوردهای دیگر حذف/بازسازی نمی‌شوند.
- مهاجرت ستون‌ها به‌صورت افزودن ستون‌های فاقد وجود و تکرارپذیر است. پیش از استقرار، از دیتابیس فعلی در Render یک پشتیبان بگیر.
- اگر فایل‌های قدیمی هنوز روی فایل‌سیستم سرویس در `static/uploads` وجود دارند، پس از استقرار می‌توانی در محیطی که به همان فایل‌ها دسترسی دارد دستور `flask --app app migrate-news-media` را اجرا کنی. فایل‌های منبع پاک نمی‌شوند. اگر Render قبلاً آن‌ها را پاک کرده باشد، این فرمان گزارش می‌دهد که فایل‌ها موجود نیستند و قادر به بازیابی‌شان نیست.
- برای پشتیبان‌گیری از PostgreSQL از قابلیت Backup/Snapshot ارائه‌شده توسط Render (در صورت دسترس‌بودن برای پلن/دیتابیس فعلی) یا خروجی `pg_dump` از همان `DATABASE_URL` استفاده کن و فایل پشتیبان را خارج از سرویس نگه دار. پیش از هر مهاجرت، یک نسخهٔ مستقل تهیه و امکان بازیابی را جداگانه بررسی کن؛ هیچ روش ذخیره‌سازی بدون پشتیبان‌گیری، تضمین مطلق نیست.
- ذخیرهٔ ویدیوهای بزرگ داخل PostgreSQL مصرف فضای دیتابیس را افزایش می‌دهد؛ فضای پلن فعلی و سقف آپلود ۱۰۰ مگابایت را پایش کن.
- صفحهٔ اصلی فقط جدیدترین خبر را بر اساس `created_at DESC, id DESC` نشان می‌دهد؛ صفحهٔ `/news` همهٔ خبرهای موجود را نگه می‌دارد. حذف خبر و حذف همهٔ خبرها فقط با نشست مدیر و درخواست POST امکان‌پذیر است؛ حذف همه نیازمند تأیید صریح است.
